= Configurer le basculement en bloc dans NetApp Data Migrator
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
Utilisez la fonction de basculement en masse dans NetApp Data Migrator pour effectuer la synchronisation finale entre vos systèmes source et de destination. Une fois les migrations de base terminées et les synchronisations incrémentales en cours, vous pouvez fusionner plusieurs chemins en une seule tâche de basculement.



== Démarrer une tâche de basculement

Suivez ces étapes pour démarrer une opération de basculement.

.Étapes
. Connectez-vous à NetApp Data Migrator.
. Sélectionnez *Serveurs de stockage* > *Serveurs de fichiers*.
. Sélectionnez le nom du serveur de fichiers pour lequel vous souhaitez créer une tâche de basculement.
. Sélectionnez *Basculement en masse*.
. Sur la page *Sélectionner le chemin*, cochez la case en regard de *Chemin source*.
. Cochez la case en regard du chemin source (confirmant la tâche de basculement).
. Sélectionnez *Procéder.*
. Cochez la case en regard du nom d'une tâche pour confirmer que vous lancez une tâche de *Bulk Cutover*.
+

NOTE: Vous pouvez sélectionner une tâche lorsqu'une tâche de migration en masse est exécutée en parallèle.

. Sélectionnez *Soumettre* pour démarrer votre tâche de basculement en masse.
+
Le message de confirmation *La tâche de basculement a été créée* s'affiche.

. Vous pouvez sélectionner le lien *View Job Listing* à côté de ce message pour ouvrir la page Job Config List où votre nouvel emploi est répertorié.




== Approuver une opération de basculement en masse

Suivez ces étapes pour approuver une opération de basculement.

.Étapes
. Sur la page *Tâches*, sélectionnez l'onglet *Job Run List*.
. Sélectionnez le menu d'actions à côté de votre tâche de basculement.
. Sélectionnez *Révision*.
+
La boîte de dialogue *Confirmation de basculement* apparaît.

. Sélectionnez le lien *Télécharger le rapport CoC*.
+
Consultez le rapport pour vérifier si le basculement a réussi et si toutes les données ont bien migré de la source vers la destination.

. Sélectionnez la case à cocher en regard de *J'ai examiné et vérifié le document de Chain of Custody (CoC) et toutes les autres informations essentielles*.
. Si vous êtes satisfait des informations contenues dans le rapport de Chain of Custody (CoC), sélectionnez *Confirmer* pour approuver le *Bulk Cutover*.
+
Le statut passe à *Terminé*.





=== Résoudre les conflits de mise à jour des métadonnées

Des conflits de mise à jour des métadonnées peuvent survenir lors du processus de confirmation de basculement pour les migrations SMB. Pour résoudre les conflits de mise à jour des métadonnées, exécutez le script de synchronisation des métadonnées pour les fichiers concernés.

.Étapes
. Téléchargez le dossier ZIP du rapport CoC généré dans le cadre du processus de basculement.
. Extrayez le dossier ZIP sur la machine de travail Windows qui a été impliquée dans la bascule pour la paire de chemins.
+

NOTE: Les lettres de lecteur  `S` et  `T` sont utilisées pour mapper les volumes source et cible sur le nœud de calcul Windows. N'utilisez pas ces lettres de lecteur pour d'autres montages lors de l'exécution de ce script.

. Copiez le fichier  `metadata_conflict_errors.csv` requis.
. Ouvrez PowerShell en tant qu’administrateur sur la machine de travail Windows.
. Accédez au répertoire des scripts :
+
[source, cli]
----
cd C:\datamigrator\scripts
----
. Exécutez le script d'estampillage des métadonnées en utilisant des espaces réservés pour tous les paramètres :
+
[source, cli]
----
.\stamp-metadata.ps1 `
-SourceHost "<SourceFileServer_FQDN_or_IP>" `
-SourceShare "<Source_ShareName_Only (e.g., data)>" `
-DestHost "<DestinationFileServer_FQDN_or_IP>" `
-DestShare "<Destination_ShareName_Only>" `
-SourceUsername "<DOMAIN User_With_Read_Access_To_Source>" `
-SourcePassword "<Password_For_Source_User>" `
-DestUsername "<DOMAIN User_With_Write_Access_To_Destination>" `
-DestPassword "<Password_For_Destination_User>" `
-InputFile "<Full_Path_To_File_List_CSV (e.g., C:\Migration\files.csv)>" `
-SidMapFile "<Full_Path_To_SID_Mapping_CSV (OldSID_to_NewSID)>" `
-Domain "<ActiveDirectory_Domain (e.g., company.com_or_COMPANY)>"
----
+
Le mappage SID et les paramètres liés au domaine (SidMapFile et Domain) sont facultatifs et peuvent être inclus selon les besoins.
